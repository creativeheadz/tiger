%lin001w
A program installed in your system has probably been not installed
by a package of your Linux packaging system. If this binary has
been installed by the administrator note that /usr/local/ is the
place for this files.
%lin002i
Installed processes listening on Internet interfaces must be
tightly controlled since they are the "open doors" to the 
outside.

A process with sockets on ports in the kernel's ephemeral range
(/proc/sys/net/ipv4/ip_local_port_range, usually 32768-60999) is reported
once for each protocol and address as "listening on ephemeral ports",
with the ports themselves in the detail. Those ports are usually chosen
by the kernel and change from run to run, so naming them in the message
would make the finding look new every time.
%lin003w
Processes that have not been run by a valid user are listening on interfaces
open to external networks. This processes might have been run by a valid user
and changed uids or might be rogue processes.

The list of valid users is defined in Tiger's configuration file (tigerrc)
variable 'Tiger_Listening_ValidUsers'. An incorrect definition there might
also lead to invalid reports and false positives.

Sockets on ports in the kernel's ephemeral range are reported once per
process, protocol and address, as for lin002i: browsers and
synchronisation clients such as Syncthing keep UDP sockets open on ports
the kernel picks, which change from run to run. To stop seeing one, add
the process to 'Tiger_Listening_ValidProcs', or accept the finding with
tigris-accept.

To fix this issue, review the value of the configuration variable and
the user the process is associated to. Confirm if the process is
running and is necessary. 

If the process is run by a system user, in order to prevent this process from
working, it is often necessary necessary to reconfigure the system to prevent
it from starting when the system boots. If this process is run by
a normal user you might need to review the processes started by login
scripts, desktop confiuration or periodic program execution.

Notice that sometimes services open sporadic UDP listeners to 
receive DNS requests, if you receive reports on open UDP services
that later on are closed this might be a false positive.

You can fix these false positives by adjusting the tiger.ignore configuration
file.
%lin004i
Netstat can be used instead of lsof in order to provide information
on listening processes, however it will provide less info since it
cannot determine the process (or PID) associated with the open socket
or the user that runs it.
%lin005f
An installed file differs from what the package that provided it
contains: its content (checksum or size) has changed. Tigris asks the
package manager's own database: dpkg's md5sums on Debian and Ubuntu,
rpm -V on Fedora, RHEL, SUSE and their relatives, apk audit on Alpine,
pacman -Qk on Arch. A change can be harmless (a file edited by hand, a
prelink or a locale tool) or a trojan put in place of a system binary by
an intruder; the message names the package so you can reinstall the file
with the package manager (apt install --reinstall, dnf reinstall,
apk fix, pacman -S) and see whether the difference goes away. Be
forewarned that an attacker with root can modify the package database
too, so a clean result is not proof of a clean system.
%lin006w
The check of installed files against package checksums could not be done
because this does not look like a Debian system, or dpkg's information is
not available. On RPM, Alpine and Arch systems the equivalent check is
reported under the same ids by pkg_integrity.
%lin006f
A file installed by a package no longer exists in the system, so it
cannot be checked. An administrator should not remove files from the
system by hand: they should be removed by uninstalling the packages that
provided them. A missing file can be an accident, an overzealous cleanup,
or an intruder removing a binary that would have exposed them. The
message names the package; reinstall it with the package manager to
restore the file. On Arch and Debian-derived minimal images, files the
administrator has declared absent (pacman's NoExtract, for example) are
not reported.
%lin007w
In the default configuration of many GNU/Linux distributions users can
reboot the machine pressing Ctrl+Alt+Delete while in console mode. This can
be considered a security risk if an attacker can easily taken down the
server from console.
You can restrict this feature through the use of the /etc/shutdown.allow
file. In that file is defined, only if a user listed in the file (or
root) are logged in will the system shutdown be initiated.
%lin008e
The /proc pseudo-filesystem is needed to check the network configuration
settings in the kernel and determine insecure setups. /proc is available
when the kernel is compiled with the CONFIG_PROC_FS=Y option (if you want
to modify them you also need to add the CONFIG_SYSCTL=Y option). You also
need to have it mounted, if it's not try: 'mount -t proc proc /proc'.
This is usually done in most distributions per default.
%lin009i
The kernel will answer (per configuration) to ICMP echo requests in any
interface. You might want to configure it to not answer to this requests
and thus make it more "invisible". Do it with:
 # sysctl -w net.ipv4.icmp_echo_ignore_all=1 
Note, however, that this violates RFCs.
%lin010f
The system will answer to ICMP broadcast echo messages. This is considered
a problem since ICMP broadcasts can cause network denial of service as
the same time as giving away the location of the hosts. To remove this do:
 # sysctl -w net.ipv4.icmp_echo_ignore_broadcasts = 1
%lin011f
The system is configured to answer to bad formatted ICMP messages. This
behavior is not recommended, please unconfigure it with:
 # sysctl -w net.ipv4.icmp_ignore_bogus_error_responses = 1
%lin012w
The system is configured to accept ICMP redirects, this might or might
not be necessary in your network topology. If you have multiple routers
to which connect through to outside locations it might be necessary,
otherwise remove it since an attacker could send bogus ICMP redirection
messages to try to route the outgoing network packets to other systems
(including his own) and thus allowing for man in the middle or
denial of service attacks:
 # sysctl -w net.ipv4.conf.all.accept_redirects = 0
and:
 # sysctl -w net.ipv4.conf.default.accept_redirects = 0
%lin013f
It is common to protect systems against Denial of Service attacks using
SYN packets (commonly known as "SYN flooding") by activating support
of TCP syncookies. Note, however, that activating this violates some RFCs:
  # sysctl -w net.ipv4.tcp_syncookies = 1
%lin014f
It is possible to send IP spoofed packets from this machine. Spoofed
packets are commonly used by trojans that make use of compromised hosts
to deliver denial of service, man in the middle or connection hijacking.
You should consider configuring your kernel to not permit this:
  # sysctl -w net.ipv4.conf.all.rp_filter = 2
and:
  # sysctl -w net.ipv4.conf.default.rp_filter = 2
%lin015w
IP forwarding is the option that permits the system to act as a router
and thus resend packets from one network interface to another. If your
system is not acting as such this option should be disabled:
 # sysctl -w net.ipv4.ip_forward = 0
%lin016f
Source routing might permit an attacker to send packets through your
host (if routing is enabled) to other hosts without following your 
network topology setup. It should be enabled only under very special
circumstances or otherwise an attacker could try to bypass the traffic
filtering that is done on the network:
  # sysctl -w net.ipv4.conf.all.accept_source_route = 0
and:
  # sysctl -w net.ipv4.conf.default.accept_source_route = 0
%lin017w
Suspicious packets received by the kernel should be logged to detect
incoming attacks. To activate this logging capability:
  # sysctl -w net.ipv4.conf.all.log_martians = 1
and:
  # sysctl -w net.ipv4.conf.default.log_martians = 1
%lin018w
The "weak end host" description in the RFC1122 permits multihomed systems
to receive packets for a network interface from another network interface.
This, as a matter of fact, removes the benefit of configuring services
and binding them to a single IP address (not to all IP addresses). 
For 2.2 kernels remove this option with:
  # echo 1 > /proc/sys/net/ipv4/conf/eth1/hidden
For 2.4 and later kernels you might need to patch the kernel or configure
your firewalling rules properly (i.e. defining anti-spoofing rules).
%lin019f
Retired in Tigris after 3.3.0: the firewall is checked by check_firewall
(fire001w, fire002w, fire003i, fire004e), which reads the nftables ruleset and
the legacy iptables tables instead of comparing "iptables -nL" with an
empty table.

The system has no firewalling rules in place to limit access to network
services and protocols. Considering configuring a set of local firewall
rules adapted to your needs. There are multiple firewall generation software 
you can use to generate these (such as Bastille, Shorewall, Firestarter,
or Knetfiler).
Local firewall rules can be used to block undesired incoming and outgoing
traffic and can be useful to prevent access to network services that are
listening on all system interfaces, only want to be used from specific
hosts (or interfaces) and lack capabilities to either restrict its
use to specific local network IP addresses or hosts. 
If the system is multi-home a local firewall configuration will prevent
spoofing attacks due to "weak end host" issues.
%lin020w
kernel.kptr_restrict is 0, so any user can read kernel addresses from
/proc/kallsyms and similar files, which defeats the randomisation of the
kernel's own layout. Set it to 1 (hidden from unprivileged users) or 2
(hidden from everyone):
  # sysctl -w kernel.kptr_restrict=1
and keep it in a file under /etc/sysctl.d/.
%lin021w
kernel.dmesg_restrict is 0, so any user can read the kernel log with
dmesg. The log shows hardware, drivers, addresses and sometimes secrets
an attacker finds useful:
  # sysctl -w kernel.dmesg_restrict=1
Note that /dev/kmsg has its own permissions (see dev004w).
%lin022w
kernel.yama.ptrace_scope is 0, so any process may attach to any other
process of the same user with ptrace and read its memory, including the
passwords and keys held by an agent or a browser. 1 restricts ptrace to
a process's descendants, which is what debuggers need:
  # sysctl -w kernel.yama.ptrace_scope=1
%lin023f
kernel.randomize_va_space is below 2, so address space layout
randomisation is partly or wholly off and every process is laid out
predictably, which is what most memory-corruption exploits rely on:
  # sysctl -w kernel.randomize_va_space=2
%lin024w
kernel.sysrq is 1, so every SysRq function is available from the console
keyboard and /proc/sysrq-trigger, including rebooting, killing all
processes and dumping memory. Distributions ship a restricted bitmask
(Ubuntu 176, Debian 438); 0 disables it entirely:
  # sysctl -w kernel.sysrq=176
%lin025w
kernel.unprivileged_bpf_disabled is 0, so unprivileged users may load
BPF programs into the kernel. The BPF verifier has been the source of
several privilege escalations. 1 disables it until reboot, 2 until the
next change:
  # sysctl -w kernel.unprivileged_bpf_disabled=1
%lin026w
kernel.perf_event_paranoid is below 2, so unprivileged users may use the
performance counters, which have been used to leak kernel data and to
mount side-channel attacks:
  # sysctl -w kernel.perf_event_paranoid=2
%lin027w
fs.suid_dumpable is 1, so a setuid program that crashes writes a core
dump, which may hold secrets, into a directory any user can read. 0
disables dumps for setuid programs; 2 writes them readable by root
only, which is what systems using a crash handler such as apport need:
  # sysctl -w fs.suid_dumpable=0
%lin028f
fs.protected_hardlinks is 0, so a user may create a hard link to a file
they do not own and cannot write. Combined with a privileged program
that writes to a path under the user's control, this is a classic way
to overwrite system files:
  # sysctl -w fs.protected_hardlinks=1
%lin029f
fs.protected_symlinks is 0, so a symlink in a world-writable sticky
directory such as /tmp is followed no matter who created it. Privileged
programs that open files in /tmp by name can then be made to open
anything:
  # sysctl -w fs.protected_symlinks=1
%lin030w
fs.protected_fifos is 0, so a program that opens a file by name in a
world-writable sticky directory can be handed a FIFO created by another
user instead, and block or read what that user feeds it:
  # sysctl -w fs.protected_fifos=1
%lin031w
fs.protected_regular is 0, so a program that creates a file with O_CREAT
in a world-writable sticky directory will happily open an existing file
planted there by another user:
  # sysctl -w fs.protected_regular=1
%lin032w
net.ipv4.conf.*.send_redirects is 1, so this host sends ICMP redirects.
Only a router has reason to; from a host they can be used to steer
other machines' traffic:
  # sysctl -w net.ipv4.conf.all.send_redirects=0
  # sysctl -w net.ipv4.conf.default.send_redirects=0
%lin033w
net.ipv4.icmp_ignore_bogus_error_responses is 0, so malformed ICMP error
responses from broken routers are logged, which lets anyone fill the
log:
  # sysctl -w net.ipv4.icmp_ignore_bogus_error_responses=1
%lin034w
net.ipv6.conf.*.accept_redirects is 1, so the host accepts IPv6 ICMP
redirects and lets any machine on the link change its routes. See
lin012w for the IPv4 equivalent:
  # sysctl -w net.ipv6.conf.all.accept_redirects=0
  # sysctl -w net.ipv6.conf.default.accept_redirects=0
%lin035f
net.ipv6.conf.*.accept_source_route is 1, so the host accepts IPv6
packets that dictate their own route. See lin016f for the IPv4
equivalent:
  # sysctl -w net.ipv6.conf.all.accept_source_route=0
  # sysctl -w net.ipv6.conf.default.accept_source_route=0
%sysd001w
The service listens on the network and systemd rates its sandboxing
UNSAFE (exposure 9.0 or more out of 10): it runs with little or nothing
between it and the rest of the system, so a flaw in it is a flaw in the
host. The message names the three unmet protections that would lower
the score most. Add them to a drop-in, for example:
  # systemctl edit UNIT
  [Service]
  NoNewPrivileges=yes
  ProtectSystem=strict
  PrivateTmp=yes
then restart the unit and run 'systemd-analyze security UNIT' to see
what remains. Services that genuinely need root or wide file access
will stay above 0 but rarely need to stay above 9.
%sysd002i
The service listens on the network and systemd rates its sandboxing
EXPOSED (exposure between 7.0 and 8.9). See sysd001w for how to read
'systemd-analyze security UNIT' and tighten it.
%sysd003i
How many of the system's services systemd rates UNSAFE and EXPOSED
overall. Most units on a desktop score badly, which is why Tiger only
warns about the ones that listen on the network (sysd001w); this line
gives the whole picture for anyone hardening a server unit by unit.
%lin036w
The kernel reports that a hardware speculation flaw (Spectre, Meltdown,
MDS, Retbleed and their relatives) is not mitigated on this machine:
the file under /sys/devices/system/cpu/vulnerabilities/ says Vulnerable,
often with the reason after a colon, such as a missing microcode update
or a mitigation turned off on the kernel command line (mitigations=off,
nospectre_v2). Update the microcode package (intel-microcode or
amd64-microcode), remove any such option from the boot command line,
and reboot. The message quotes the kernel's own text.

%boot002f

%boot003w

%boot004f
The GRUB configuration file is readable by everyone. It can hold a boot

%boot005w

%boot006w
LILO is not configured with a password, so anyone at the console can
boot with init=/bin/sh or single and get a root shell. Add password=
and restricted to lilo.conf, make the file 0600 and rerun lilo.
%boot007w
LILO has "restricted" set, which only has an effect together with a
password, and no password is configured. Add password= to lilo.conf,
make the file 0600 and rerun lilo.
%boot008w
GRUB is not configured with a password, so anyone at the console can
edit the boot entry (init=/bin/sh, single) and get a root shell. Set a
superuser and a password with grub-mkpasswd-pbkdf2 in
/etc/grub.d/40_custom and regenerate the configuration. On a machine
without console access by untrusted people this may be acceptable.

%lin038w
A file installed by a package has a different mode or owner than the
package set. The check asks the package manager (rpm -V, apk audit,
pacman -Qk), so it covers RPM, Alpine and Arch systems; the dpkg checks
compare content only. A binary that has become world-writable, or
changed owner, can be replaced by whoever it now belongs to. Restore it
with the package manager's own tool (rpm --setperms PACKAGE, apk fix
PACKAGE, pacman -S PACKAGE) or, if the change is intended, accept the
finding with tigris-accept.
